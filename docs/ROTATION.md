# Як працює розклад чергувань (rotation)

Коротко: розклад **детермінований** — він повністю обчислюється з двох речей:
**дати старту** (`startDate`) і **списку підтверджених мешканців** (з кімнатами
A/B). Жодного випадкового вибору — тому кожен телефон показує **один і той самий**
розклад без сервера. Ручні заміни (swap) зберігаються «зверху» як винятки.

## Ролі (що саме чергують)

У кожній буньці 4 ролі щотижня:

| Роль | Іконка | Хто робить | Зона |
|------|--------|-----------|------|
| **ROOM_A** | 🛏️ | мешканці **кімнати A** (між собою) | прибирання своєї кімнати |
| **ROOM_B** | 🛏️ | мешканці **кімнати B** (між собою) | прибирання своєї кімнати |
| **KITCHEN** | 🍳 | будь-хто з буньки | кухня + винос сміття (спільне) |
| **BATHROOM** | 🚿 | будь-хто з буньки | ванна + WC (спільне) |

Ідея: **свою кімнату прибирає своя кімната**, а **спільні зони** (кухня, ванна)
розподіляються на всю буньку по черзі.

## Логіка «хто цього тижня»

Позначимо `W` — номер тижня від дати старту (0, 1, 2, …). Він рахується так:
`W = (понеділок цього тижня − понеділок startDate) / 7`.

**Кімнатні ролі** (кожна кімната крутиться сама по собі):
- `ROOM_A` = список кімнати A по колу: `A[ W mod (к-сть у кімнаті A) ]`
- `ROOM_B` = список кімнати B по колу, але **зі зсувом +2**:
  `B[ (W + 2) mod (к-сть у кімнаті B) ]`

Зсув +2 у кімнати B потрібен, щоб дві кімнати були «не в фазі» — тоді той самий
тиждень рідше дає одній людині і кімнату, і спільну зону.

**Спільні ролі** (кухня/ванна) — беруться з тих, хто цього тижня **НЕ** черговий
по кімнаті:
1. беремо всіх підтверджених мешканців буньки → `all`;
2. викидаємо тих, хто цього тижня вже черговий по `ROOM_A` і `ROOM_B` →
   лишається `remaining`;
3. кухня = `remaining[ (W*2 + 0) mod k ]`, ванна = `remaining[ (W*2 + 1) mod k ]`
   (два різні «слоти», щоб кухня і ванна дісталися різним людям);
4. якщо людей замало і `remaining` порожній — беремо з `all` (щоб не було
   «нікого»).

Через `W*2 + слот` кожного наступного тижня спільні зони зсуваються далі по
колу — так чергування «повзе» рівномірно: кожен по черзі стає черговим, один за
одним, без пропусків.

## Приклад (бунька з 4 людей у кімнаті A і 4 у кімнаті B)

- Тиждень 0: ROOM_A = A₀, ROOM_B = B₂, кухня/ванна — двоє з тих, хто вільний.
- Тиждень 1: ROOM_A = A₁, ROOM_B = B₃, кухня/ванна — інші двоє.
- … і так по колу; за кілька тижнів кожен побуває в кожній ролі.

Вкладка **«Rozpis služeb»** показує весь розклад по тижнях (можна гортати
вперед/назад), а **«Body»** показує лічильник справедливості — скільки разів
кого поставлено в чергу (щоб було видно, що навантаження рівне).

## Заміна чергового (hand-over / swap)

Якщо хтось не може — на картці чергування є кнопка 🔄. Заміна записується як
**override** на конкретний тиждень+роль: `overrides["2026-W36|KITCHEN"] = memberId`.
Це не ламає загальний розклад — лише цей один тиждень для цієї ролі призначається
вручну. Прибрати заміну → повертається справедливий автоматичний вибір. Усі
заміни логуються в історію (хто → кому, коли).

## Важливо: спільний список мешканців

Розклад однаковий для всіх, **лише якщо список мешканців однаковий на всіх
пристроях**. Мешканці беруться з таблиці `memberships` (підтверджені акаунти
буньки). Щоб кожен бачив усю буньку (а не лише себе), RLS-політика `p_mem_sel`
дозволяє **будь-якому підтвердженому учаснику** читати рядки своєї буньки
(див. `schema-auth.sql`). Без цієї політики звичайний учасник бачив би лише себе
— і тоді програма показувала б його єдиним мешканцем (і завжди «черговим»).

## Кімнати A/B

Кімната кожного мешканця задається адміном (у панелі 🛠️, поле A/B) або самим
мешканцем при вступі. Якщо всі в одній кімнаті — розклад теж працює, але
вироджено (одна кімната крутиться, друга порожня). Для нормального чергування
розподіли людей між A і B.
