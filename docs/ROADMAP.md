## 💸 Погашення боргу (два шляхи) ✅
- [x] Борг накопичується **на кожну людину**: купив на 90 → кожному з 7 співмешканців ~по частці; наступна покупка іншого додає до сумарного балансу. *(Splitwise-баланси — уже було)*
- [x] Погасити борг: **(а) переказ грошей** + прикріпити фото банківського підтвердження, або **(б) купити річ на еквівалентну суму** для всіх.
  - Кнопка «Vyrovnat» відкриває вибір із двох шляхів; переказ приймає фото-доказ (стискається в мініатюру, працює офлайн), купівля на всіх додається як спільний виток.
  - **Перевірка справжности чека ШІ** — серверна функція `verify-transfer` готова; вмикається після Supabase + ключа ШІ (див. `HANDOFF.md`, Крок 3). Без неї фото просто зберігається як доказ.

## 🏷️ «Ідеальний товар» (антипереплата)

## 🏆 Гейміфікація і мотивація ✅ (готово)
- [x] **Тижневий «великий прибирання» (місячний) тиждень = ×2 бали** — мотивує на важкий тиждень.
- [x] **Купівля зásob для буньки = +3 бали** (за зусилля + гроші наперед) — «shopping-карма». Логуються з `by`+`ts`.
- [x] **Серії 🔥** — скільки служб поспіль виконано на 100%; показуються в таблиці балів.
- [x] **Герой місяця 🏅** — найактивніший за поточний календарний місяць отримує винагороду (за замовч. 100 CZK, налаштовується). Новий місяць — новий старт.
- [x] Правила оновлені в таблиці балів; бали годують рівні (tiers) і жетони імунітету.

## 📸 Підтвердження виконання фото + ШІ ✅ (Фаза 3 — готово)
- [x] Фото **лише з камери в застосунку** (без вибору з галереї) — через `getUserMedia` (жива камера + кадр у canvas). Модуль `js/camera.js` (перемикання камери, повторне фото, тільки жива зйомка).
- [x] ШІ підтверджує, що завдання **справді виконано** (фото сцени відповідає завданню) — функція `supabase/functions/verify-task/index.ts` (Claude vision), клієнт `js/verifytask.js`.
- [x] **Антиспуф**: ШІ визначає, чи це не фото екрана (ноут/телефон) — муар, рамка, пікселі. Частина того ж `verify-task` (поле `spoof`).
- [x] Налаштування «коли вимагати фото»: вимкнено / тижневі+місячні / усі. Плавна деградація без ШІ або без камери. Мініатюра-доказ зберігається локально біля завдання.

## 🏢 Мультибуньки + кімнати + панель адміна ✅ (готово, увімкнено за замовчуванням)
- [x] Модель: **буньк­а** (напр. 2) + **кімната A/B** (по 4 людини) → «2A», «2B». По всьому гуртожитку — багато буньок, у кожній кімнати A/B.
- [x] **Супер-адмін (Арсен)**: схвалює створення нових буньок і призначає **адмінів буньок**.
- [x] **Адмін буньки**: схвалює людей у СВОЮ буньку (кожен адмін — свою).
- [x] **Панель управління** (адмін-екран): буньки, кімнати, заявки, ролі.
- [x] **Справжні логіни** (Supabase Auth) — тепер **режим за замовчуванням** для всіх (`CONFIG.authMode`). Аварійний вихід: `?auth=0` (або кнопка «Продовжити без входу» на екрані помилки) повертає локальну версію на чесності.
